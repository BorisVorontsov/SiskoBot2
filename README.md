# bashorg-tg-bot

Автономный Telegram-бот, который публикует цитаты из «Цитатника Рунета»
([башорг.рф](https://башорг.рф/)) в группу, где он состоит. Запускается один раз
и работает бесконечно: выбрал цитату из **архива** (весь диапазон дат с
01.01.2020 и до сегодня) → опубликовал → уснул на случайно сгенерированный
интервал **2–6 часов** → повторил.

## Как это работает

1. RSS `https://башорг.рф/rss/` используется как «часы»: он отдаёт самые свежие
   ID, по которым определяется максимальный ID цитаты на сегодня.
2. Пул цитат — **весь архив с 01.01.2020**: ID цитат растут в порядке публикации,
   поэтому период однозначно покрывается диапазоном ID. Нижняя граница (первая
   цитата 2020 года) ищется один раз бинарным поиском по страницам
   `/quote/<ID>` и запоминается в базе.
3. Каждый цикл бот равномерно «вытягивает» случайный ID из диапазона и берёт
   страницу `/quote/<ID>` (роботы её не запрещают). С сайта снимаются: номер
   цитаты, текст (HTML разворачивается в обычный текст с переносами строк),
   дата публикации, постоянная ссылка.
4. Уже опубликованные ID и цитаты старше 01.01.2020 отсеиваются; удалённые
   цитаты (заглушки без даты) пропускаются.
5. Случайно выбирается **одна** новая цитата и отправляется в чат
   (`parse_mode=HTML`, длинные цитаты аккуратно разбиваются на несколько
   сообщений — текст не теряется).
6. Цитата помечается опубликованной **строго после** успешной доставки.
7. Бот спит случайный интервал от `MIN_INTERVAL_HOURS` до `MAX_INTERVAL_HOURS`
   (по умолчанию 2–6 часов) и повторяет цикл.

Источник цитат не ограничивается последними 100 записями RSS — пул 2020–2026
огромен, поэтому на годы вперёд бот не упрётся в «новых цитат нет».

Если новых цитат нет или сайт недоступен — повторная попытка через 30 минут
(экспоненциально до часа после ошибок Telegram), сайт не нагружается.

Стек: **Python 3.12**, [python-telegram-bot](https://docs.python-telegram-bot.org/)
(официальный Bot API), [httpx](https://www.python-httpx.org/),
SQLite из стандартной библиотеки. Зависимостей всего три.

## Получение токена бота

1. В Telegram найдите [@BotFather](https://t.me/BotFather) → команда `/newbot`.
2. Придумайте имя и username бота (username заканчивается на `bot`).
3. BotFather выдаст токен вида `1234567890:AAAbbb...`. Он хранится только
   в `.env` — в коде и Git его быть не должно.

## Добавление бота в группу и права

1. Добавьте бота в нужную группу как участника (обычное добавление контакта).
2. Обязательно снимите у бота privacy mode **или** выдайте права администратора:
   - вариант A: BotFather → `/mybots` → ваш бот → *Bot Settings* →
     *Group Privacy* → *Turn off*;
   - вариант B: в настройках группы сделайте бота администратором
     (любые права, достаточно «удаление сообщений»).
3. Если `TELEGRAM_CHAT_ID` не задан, бот сам определит группу, когда окажется
   в ней, и сохранит её ID в базу.

> Без отключённого privacy mode и без прав администратора бот может не видеть
> события группы; публикация при этом всё равно возможна, если задан
> `TELEGRAM_CHAT_ID` явно.

## Команды бота

| Команда | Действие |
|---|---|
| `/help` | список команд |
| `/next` | внеочередная публикация новой цитаты |

Где работают команды:

- **В личных сообщениях боту** — всегда, без дополнительных настроек.
  `/next` опубликует цитату в настроенную группу, `/help` ответит в личку.
- **В группе** — только если бот видит сообщения группы: privacy mode
  отключён (BotFather → *Bot Settings* → *Group Privacy* → *Turn off*)
  или бот является администратором группы. Иначе Telegram не доставляет
  боту сообщения группы — используйте личные сообщения либо дайте права.

Команды обрабатываются в паузах между публикациями; неизвестные команды
игнорируются.

## Как узнать CHAT_ID

Обычно не нужно — бот определит его сам. Ручные способы:

- Напишите боту в личку — он залогирует подсказку `TELEGRAM_CHAT_ID=<ваш id>`
  (для личного чата ID положительный).
- Для групп: добавьте в группу любого бота вроде @getidsbot, он покажет
  `-100…` ID группы.
- Либо посмотрите сохранённое значение в базе:
  `sqlite3 data/state.db "SELECT * FROM state;"`.

Установка зависимостей и запуск локально (Linux):

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt          # для разработки: -r requirements-dev.txt

cp .env.example .env                     # впишите TELEGRAM_BOT_TOKEN
python -m bot                            # основной режим (бесконечный цикл)
python -m bot --once                     # один цикл публикации и выход
```

## Запуск через Docker

```bash
cp .env.example .env    # впишите токен
docker compose up -d --build
docker compose logs -f  # смотреть логи
```

Compose монтирует volume `bot-data` → `/app/data`: состояние переживает
пересоздание контейнера. Политика перезапуска — `unless-stopped`.

Запуск без compose:

```bash
docker build -t bashorg-tg-bot .
docker run -d --name bashorg-tg-bot \
  --env-file .env \
  -v bashorg-tg-bot-data:/app/data \
  --restart unless-stopped \
  bashorg-tg-bot
```

## Конфигурация (переменные окружения)

| Переменная             | По умолчанию            | Описание                                   |
|------------------------|-------------------------|--------------------------------------------|
| `TELEGRAM_BOT_TOKEN`   | — (обязателен)          | Токен от @BotFather                        |
| `TELEGRAM_CHAT_ID`     | автоопределение         | ID чата для публикации (у групп `< 0`)      |
| `MIN_INTERVAL_HOURS`   | `2`                     | Нижняя граница случайной паузы, часы       |
| `MAX_INTERVAL_HOURS`   | `6`                     | Верхняя граница случайной паузы, часы      |
| `DB_PATH`              | `data/state.db`         | Файл SQLite с состоянием                   |
| `FEED_URL`             | `https://башорг.рф/rss/`| URL RSS-ленты                              |
| `SITE_BASE_URL`        | `https://башорг.рф`     | База сайта для ссылок                      |
| `HTTP_TIMEOUT_SECONDS` | `30`                    | Таймаут запросов к сайту                   |
| `LOG_LEVEL`            | `INFO`                  | `DEBUG` / `INFO` / `WARNING` / `ERROR`     |

## Где хранится состояние

SQLite-база `data/state.db` (в Docker — `/app/data/state.db` на volume):

- таблица `published` — ID опубликованных цитат с временем публикации;
- таблица `state` — определённый автоматически `chat_id` и граница архива
  (`archive_start_id` — первая цитата от 01.01.2020).

Перезапуск процесса или контейнера ничего не теряет: бот не опубликует одну и
ту же цитату дважды.

## Логи

Пишутся в stdout (Docker собирает их через `docker logs`). Формат:
`YYYY-MM-DD HH:MM:SS LEVEL logger: сообщение`, время в UTC. В логах видно
запуск, размер ленты, выбор поста, успешную публикацию, время следующей,
ошибки HTTP/Telegram/парсинга и восстановление. Токен никогда не выводится
(включая случай невалидного токена).

```bash
journalctl -u bashorg-bot -f        # если запущено как systemd-сервис
docker compose logs -f              # в Docker
```

Пример systemd-юнита (`/etc/systemd/system/bashorg-bot.service`) без Docker:

```ini
[Unit]
Description=Bash.org.ru -> Telegram quotes bot
After=network-online.target
Wants=network-online.target

[Service]
User=youruser
WorkingDirectory=/opt/bashorg-tg-bot
EnvironmentFile=/opt/bashorg-tg-bot/.env
ExecStart=/opt/bashorg-tg-bot/.venv/bin/python -m bot
Restart=always
RestartSec=30

[Install]
WantedBy=multi-user.target
```

## Как обновлять бота

```bash
git pull
# без Docker:
source .venv/bin/activate && pip install -r requirements.txt && sudo systemctl restart bashorg-bot
# с Docker:
docker compose up -d --build
```

Состояние (volume/каталог data) остаётся на месте — история публикаций
сохраняется.

## Ограничения и заметки

- Источник данных — страницы `/quote/<ID>` в диапазоне дат с 01.01.2020, RSS —
  только «часы» максимального ID; robots.txt чтение страниц цитат не запрещает.
  CAPTCHA/paywall у сайта нет, никаких механизмов защиты бот не обходит.
- Рейтинг цитат в RSS не отдаётся, поэтому в сообщении публикуются номер, дата
  и ссылка на оригинал.
- Если новых цитат нет (публиковать нечего) — повторная попытка через 30 минут.
- Если бот исключён из группы, сервис завершается с понятной ошибкой;
  супервизор (systemd/Docker) перезапустит его, и он снова будет ждать
  добавления (при пустом `TELEGRAM_CHAT_ID`).
